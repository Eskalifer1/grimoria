# i18n and copy conventions

Catalogs, keys, namespaces, and how the two tonalities are written. _Why_ the system has this
shape is `docs/adr/0004-copy-system-locale-x-theme.md`.

## Adding a string

1. Pick the owning module → that is the namespace.
2. Add the key to `messages/en/standard.json`.
3. Write the dark-fantasy value for the same key in `messages/en/dark-fantasy.json` — `tsc`
   will not let you defer it.
4. Invented a term? Add it to the mapping table in the same change.
5. `yarn check:fix` sorts both catalogs.

## The catalogs

```
messages/en/standard.json       client app, standard Theme
messages/en/dark-fantasy.json   client app, dark-fantasy Theme
```

The active Theme selects **which catalog loads**, never which key is read, so no component ever
names a Theme. Two per locale is all there is — every surface of ours is themed, and Payload's
admin at `/cms` ships its own translations. Why a catalog per Theme rather than a namespace
inside one is ADR-0004.

**Both theme catalogs are complete.** Dark-fantasy is not a sparse overlay: `src/i18n/
messages.ts` constrains every theme catalog to `standard`'s key set, so a forgotten key is a
`tsc` error naming it rather than standard copy leaking into the fantasy UI at runtime. Keys,
structure and nesting are identical; only values differ.

**Key order is automatic** (`useSortedKeys`). Do not hand-order or group by importance — the
point is that both catalogs read line-for-line against each other.

## Keys and namespaces

Short semantic keys, camelCase, at most three segments: `<namespace>.<element>[.<role>]` —
`homePage.title`, `noteForm.title.placeholder`. The third segment is a role (`label`,
`placeholder`, `aria`, `error`) added only when one element genuinely owns more than one
string.

A key describes what the string **is**, not what it currently **says**: `emptyState`, not
`youHaveNoNotesYet`. **Sentence-as-key is forbidden** — two catalogs hold two different
sentences for one key, so there is no sentence the key could be.

**A namespace is the module that owns the string**, camelCased from the folder name — not the
route. `NoteCard` renders on the notes list _and_ the public page, so a `notes` namespace would
force it to duplicate its strings or read them from a page it knows nothing about. Renaming a
component means renaming its namespace: a namespace with no module is dead copy, and it stands
out.

**`common` is for the genuinely ownerless** — `save`, `cancel`, `appName`. The test is "belongs
to nobody", not "used more than once": a string used by two note screens belongs to the note
module. An unclear owner is a question about where the component belongs.

## Reading copy

**`useTranslations` by default**, in Server and Client Components alike. `getTranslations` and
`getFormatter` are for already-async contexts without hooks: `generateMetadata`, Server
Actions, route handlers.

**A component reads its own namespace.** Passing an already-translated string down as a prop
hides where the text came from. A screen module passing a whole `ReactNode` is composition, not
copy threading.

**`shared/` never calls `t`.** It is defined by having no domain attachment, and copy is always
domain-bound — a `Button` reading `common.save` stops being reusable the moment a screen needs
"Publish". `shared/` receives text as props or `children`; `entities/`, `features/` and
`views/` call `t` directly at any depth.

**The exception is a vocabulary declared in `src/constants/`.** A shared set every layer answers
with has no domain to bind to and no module above `shared/` that owns it, so it is worded where it
is consumed. There are five: **`ACTION_ERROR` and `OPTIMISTIC_ERROR` under `actionError`**, worded by
`src/shared/hooks/useActionErrorMessage.ts` — a code is its own key, in one namespace, whichever of
the two it came from; **`VALIDATION_ERROR` under `validation`**, worded by
`src/shared/hooks/useValidationMessage.ts`, one sentence per rule with its bound as `limit`
(`docs/features/forms.md`) — those two worded in `src/shared/hooks/`, where the code is turned into
a sentence; **the `optimistic` namespace**, the words the write-state components say for themselves
(`dismiss`, `pending`, `offline`, `problem`); **the `form` namespace**, the words a form
draws without being told (`save`, `cancel`); and **the `toast` namespace**, the words the one
transient surface says for itself — its region label, its dismiss, and the confirmations
`TOAST_MESSAGE` in `src/constants/toast.ts` names — those three read with `useTranslations` inside
`src/shared/components/`.

## Writing the message

- **Anything that varies lives in the message, as ICU** — plurals, interpolation, and `select`
  for a variant that changes the whole sentence. A conditional picking between two `t()` calls
  is usually a `select` that was not written.
- **`t.rich` for markup inside a sentence.** Splitting a sentence into two keys to wrap its
  middle cannot be reordered by a translator.
- **Dates and numbers go through `useFormatter`** — not `toLocaleString`, not `Intl.*` by hand,
  not a date library's locale handling, all of which scatter locale decisions across
  components.
- **A translation is never an argument to another translation.** It reads as a sentence in
  English and as nothing in particular anywhere else, and breaks agreement in both tonalities.

```jsonc
"count": "{count, plural, =0 {No notes} one {# note} other {# notes}}",
"terms": "Read the <link>terms</link> before publishing."
```

## What must come from a catalog

**Everything the user reads or hears**, including what never appears on a screenshot:
`aria-label`, `alt`, `title`, `placeholder`, visually-hidden text; `generateMetadata` output;
error, validation and empty-state messages.

Three deliberate exceptions, and one not on this list is a bug rather than a judgement call:
**Payload collection and field labels**; **copy inside design mockups**; and **developer-facing
strings** — logs, thrown `Error` messages, test fixtures.

A **dev-only surface** may be exempted as a fourth — no User reaches it, so translating it would ship
two catalog entries per label to everybody for nothing. There is none today. One that earns it is
exempted by path in `biome.json`, and is deleted rather than translated.

`style/noJsxLiterals` catches visible text in JSX, and is off in `ui/` and in the test
trees. Its strict mode (`noStrings`) is not enabled, so a literal in `aria-label`, `alt`,
`placeholder` or `title` is caught by review rather than by Biome.

## Navigation

**Inside the localized tree, navigate through `src/i18n/navigation.ts`** — its `Link`,
`redirect`, `usePathname`, `useRouter`, `getPathname`. `next/link` and `next/navigation` drop
the active locale there. Outside it — `(payload)` — plain `next/*` is correct.

Everything of ours is inside it: `src/app/(frontend)/[locale]/**`, served by
`src/i18n/request.ts`, which picks `messages/<locale>/<theme>.json`. Which Theme is active is
decided in exactly one place, `src/i18n/resolveTheme.ts`.

**The Themes themselves are `src/constants/theme.ts`** — the `THEMES` list, the `Theme` type
derived from it, `DEFAULT_THEME` and the cookie name. `src/i18n/theme.ts` holds only the guards
that narrow an outside value to a `Theme` (`isTheme`, `toTheme`).
